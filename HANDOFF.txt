DECISIONS MADE (with Trey's approval, 2026-10-11)
  - Database: PGlite (Postgres-in-WASM, ./data/pglite) because
    Docker/Postgres are NOT installed. DATABASE_URL switches to real
    Postgres with no code change. PGlite allows ONE process at a
    time: never run worker + MCP/dashboard concurrently.
  - pgvector via @electric-sql/pglite-pgvector (separate package in
    PGlite 0.5.x; the in-package "/vector" export no longer exists).
  - ORM: Drizzle (not Prisma): native PGlite driver, schema.ts is the
    source of truth, vector column type built in. After editing
    schema.ts run `npm run db:generate`; migrations apply on connect.
  - Claims come from TWO sources: deterministic RULES over trials
    (aggregate/rules.ts) for the structured kinds, plus ONE LLM pass
    (aggregate/llm.ts) for open-ended discovery. Rules alone already
    find real divergences; the LLM pass is additive and activates
    only when ANTHROPIC_API_KEY is set.
  - LLM: claude-opus-5-5 via @anthropic-ai/sdk, beta messages stream,
    output_config.format json_schema + ajv re-validation, adaptive
    thinking, server-side refusal fallback "default". Model is
    swappable via AUTOPIA_MODEL; provider via src/llm/adapter.ts.
  - Reproduction compares a normalized SIGNATURE (status, body kind,
    JSON shape, error message on 4xx/5xx only), never raw bytes.
  - Every claim has a stable claim_key (rules: rule:<rule>:<endpoint>:
    <param>; llm: llm:<kind>:<endpoint>:<param>:<verdict>:<probes>)
    and "expectations" (trial id -> expected status), making the
    evidence check mechanical for rules AND LLM claims.
  - Pipeline order deviates from spec 7.2 on purpose: the free
    EVIDENCE CHECK runs BEFORE cross-ref self-consistency. Reason: an
    LLM claim that mis-states a trial's status would otherwise
    "contradict" correct rules claims citing the same trial and
    quarantine them. Found by the integration test.
  - Self-consistency contradiction = (1) two claims expect different
    statuses for the same trial, or (2) same endpoint+kind+param,
    accepts vs rejects, over IDENTICAL evidence sets. Sharing only
    the comparison baseline is NOT a contradiction (first live run
    quarantined 44 good claims before this fix).
  - Claims belong to a test_run; "current claims" = latest finished
    run of a version. Lets us check determinism across runs.
  - Search: Postgres full-text (OR of query words, ranked), ILIKE
    fallback. Embedding column exists, left NULL (needs Voyage or
    similar; Anthropic has no embedding model).
  - Confidence is derived from evidence count, not model-reported.
  - "Insufficient evidence" = no claim (not a claim kind).

BATTERY 1.2.0 (2026-10-11): PATH PARAMS + SCHEME-TARGETED AUTH
  - Path parameters now get the same per-parameter probes as query
    params (wrong type, enum, null, EMPTY SEGMENT, boundaries, long
    string), substituted into the URL. TrialInput.pathParams records
    the values; rules/LLM summary read them. Path params cannot be
    'omitted'; the empty segment is the probe.
  - Auth probes read the spec's apiKey securitySchemes (spec.ts
    EndpointSpec.authSchemes) and emit bad_auth:<name> (invalid value)
    and no_auth:<name> (header value '' = executor sends NO such
    header, including its own default User-Agent). Falls back to the
    old heuristics only when the spec declares no apiKey scheme.
  - Why: NWS run #10 said 'invalid credential accepted' because we
    sent Authorization: Bearer, a header NWS never reads. Its real
    gate is User-Agent (403 when missing); the X-Api-Key scheme is
    declared but not enforced. Probing the wrong header told us about
    our probe, not the API. Lesson: read the security block.

  #12/#13 rejected 24/18 TRUE claims on that endpoint because the
  stored and fresh signatures differed inside features[0]. The gate

  1. signaturesEqual compares shapes for COMPATIBILITY: 'null' matches

COST CONTROLS + RETENTION (2026-10-12)

    ('run-all --no-llm --prune-days 14', free); run-all-llm.yml =
    WEEKLY (Sunday 08:00 UTC) with the LLM pass. Model cost drops ~85%.
  - CARRY-FORWARD (src/worker/aggregate/carry.ts): every run re-admits
    the previous run's LLM claims as candidates, remapping each cited
    trial to tonight's trial with the same endpoint+mutation id and
    keeping the expected status; then evidence check + reproduction
    as usual. Fresh LLM claims win key ties (crossref dedupe keeps the
    first). A carried claim whose behavior changed fails the evidence
    check and is dropped. Summary shows 'carried N (M unmappable)'.
  - RETENTION (src/db/retention.ts, CLI 'prune [days]' / run-all
    '--prune-days N', '--dry-run'): deletes runs older than N days
    with their claims+trials, EXCEPT the latest finished run per
    version and runs whose claims a claim_diff cites.
  - Tests: tests/unit/carry.test.ts, tests/integration/retention.test.ts
    (carry across rules-only runs, drop on changed behavior, prune
    keeps latest). Suite: 75.
