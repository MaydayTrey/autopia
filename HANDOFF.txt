     Original design notes follow.
  3. CONTRIBUTOR-VERIFIED TIER for keyed/paid APIs (last). Design:
     - The contributor runs the open-source worker LOCALLY with their
       own API key and their own model key. Nothing secret reaches us.
     - Upload contains ONLY: claims + evidence as status code and
       SIGNATURE (type shape, no values) + probe ids. NO response
       bodies, NO error-message text, NO header values. Shapes cannot
       carry names/account numbers. (Trey's concern: we must not rely
       on scrubbing bodies; so never receive them.)
     - Claim statements are the one remaining leak path: the local
       worker shows every statement for approval before upload, and
       the server scrubs/rejects statements containing emails, tokens,
       long digit runs.
     - Sheets label the tier: 'contributor-verified by key <prefix> on
       <date>, not re-verified since; evidence limited to status and
       shape'. Server cannot re-run keyed trials; the date is the
       honesty mechanism.
     - PREREQUISITE before any keyed target even locally: redact
       credential headers from stored trial inputs (today target
       headers are copied into every trial row).
